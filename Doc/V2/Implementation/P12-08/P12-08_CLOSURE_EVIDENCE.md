### cp1252 packaged-runtime verification

**Result: CASE A — the packaged GUI does not reproduce the failure.**

1. The risk exists in Core: `DocxPostProcessor` prints emoji diagnostics, and
   writing such a character to a cp1252 stream raises `UnicodeEncodeError`.
2. The accepted packaged build is windowed: the process has no console window
   and redirected stdout/stderr captured 0 bytes.
3. `print()` with `sys.stdout = None` (the windowed packaged situation) returns
   silently; verified in the interpreter used for the build.
4. The emoji-printing code path executes during a packaged conversion: the
   produced DOCX contains the native TOC field (`TOC \o`) generated by that same
   post-processing block, and the conversion reached SUCCESS.
5. `PYTHONIOENCODING` was empty for every verification run; no environment
   workaround was used and no Core change was made.
